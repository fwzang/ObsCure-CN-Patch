## ✨ 这个补丁做了什么

### 技术路线

游戏用 `grp1` 字库纹理渲染文字。补丁通过：

1. 在游戏目录放一个 **`version.dll` 代理**（游戏会先加载它）
2. 代理转发全部导出到真实 `version.dll`，同时挂钩 **D3D9 的 `SetTexture`**
3. 识别到游戏绑定 `grp1` 字体纹理时，换成**内嵌的中文图集**
4. 配套修改数据包里的**文本与字形表**（def），让中文按新字形度量排版

### 两个安装版本

| 版本 | 内容 |
|---|---|
| 精简版 | 汉化必需组件（代理 + 图集 + 文本/字形表） |
| 加强版 | 在精简版基础上加高清素材与字体增强 |

### 字体

- 纯白 **#FFFFFF**（RGB 层；alpha / 字形表 / 位置不动）
- V1 投影 + V4b 端黑英文字形

## ⚠️ 已知限制（重要，请先读）

### 1. 「图集糊墙 / 文字延迟」是**结构性现象**，不是 bug

当前 hook 机制**只有「绑定时替换」一条路径，不存在任何还原路径**。
因此当引擎把字体纹理当作别的用途绘制时，会短暂看到图集内容。

这一点已做过多轮尝试（改 cave、静态拆弹、方案 B 推演），结论是**靠改 hook 无法消除**，
详见 `03_文档/报告_2026-10-26/技术死结论报告_最终核验_2026-10-26.md`。

**实际影响**：切场景/加载时偶发一瞬，进入游戏后不影响游玩。

### 2. 其它

- 部分场景文字排版仍有溢出
- 版权条等**位图内文字**未汉化
- Steam 成就名称/描述不汉化（数据在服务端）

## 🔧 从源码构建

### 代理 DLL（`version.dll`）

```bash
# 32-bit mingw-w64（游戏是 32 位进程）
i686-w64-mingw32-gcc -O2 -shared -o version.dll <源码>.c version.def
```

源码位置：`05_hook源码与译文/`（含 `hook_patch_*` / `hook_cave_*` 各阶段快照）。

### 安装器

```bash
cd 02_源码/安装器        # 或 安装器_v2/
# 安装器把载荷按 O1SETUP2 格式追加到 exe 末尾
```

载荷清单与格式说明见 `01_安装包/README_安装包结构.md`。

### 校验

```bash
python 02_源码/产线工具/verify_mask_state.py    # 发布前必跑：确认是「切屏黑屏遮罩版」
```

> **发布硬性断言**：`version.dll` 偏移 `0x37954` 必须是 `73 24`（遮罩版）。
> 若是 `EB 24` 说明是"关掉遮罩"的实验件，**禁止发布**。

## 🧭 技术要点（给想接手的人）

1. 游戏是 **RenderWare + D3D9**，字库在 `grp1`，纹理格式与尺寸见反编译笔记。
2. **`version.dll` 代理是唯一加载点** —— 游戏从系统目录链式加载，代理必须在游戏根目录。
3. 字体替换**没有还原路径**，这是机制决定的结构性缺陷（见上方"已知限制"）。
4. 发布前必须跑 `verify_mask_state.py`，确认遮罩状态。
5. 数据包读写用 `02_源码/产线工具/工具二进制_hvptool/`（HVP 包工具，需 zlib）。
