### Q1 日志落盘逻辑

| 环节 | 结论 |
|---|---|
| 写入函数 | 两个独立函数（对应 `VPLOG`/`HKLOG`）：`0x100019E0`（versionproxy.log）、**`0x10001A60`**（x_hook.log） |
| 路径构造 | `<目录缓冲 0x10041460>` + 文件名（`lstrcatA` 拼接）→ 存入 `0x10041708` → 传给 `CreateFileA` |
| 目录构造（`0x10001720`–`0x1000176F`） | ① 基目录 `0x1004108c` = **`.\`（当前工作目录，相对路径）** ② 拼 `hzp_tools\out\` 得 `.\hzp_tools\out\` ③ `GetFileAttributesA` 检查是否目录 ④ **是目录 → 用它；不是 → 回退到基目录 `.\`** |
| 打开方式 | `CreateFileA(path, FILE_APPEND_DATA(4), share=3, NULL, OPEN_ALWAYS(4), 0x80, 0)` |
| 失败行为 | `cmp eax,-1` / `je` → **静默跳过**。不创建目录、不 fallback 到别处 |

对照 c86 源码 `version_proxy.c:70-77`，结构完全一致：
```c
HANDLE h = CreateFileA(file, FILE_APPEND_DATA, ..., OPEN_ALWAYS, ...);
if (h == INVALID_HANDLE_VALUE) return;   // 失败静默
```
区别仅在路径：c86 写死 `D://SteamLibrary//...`（:63-64），**c93e 改为相对路径**。

### Q3 如何控制 —— **没有开关**

c93e 字符串内无 `NO_LOG`/`LOG_OFF` 之类总闸；c86 的 `P1_DIAG_PROBES` 只管"探针"、不管日志本身。

三个可选方案：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A2a（已定，推荐）** | 二进制补丁：只把 `dwCreationDisposition` 由 `OPEN_ALWAYS(4)` 改成 `OPEN_EXISTING(3)`，**共 2 字节**（FOFF `0xE15`、`0xE95`）。文件不存在 → `CreateFileA` 返回 `-1` → 走已有 `je` 失败路径 | 改动最小、栈天然平衡、零副作用 |
| A2b（备选） | 11 字节无条件跳转：`83 C4 1C` + `E9 29 00 00 00` + `90 90 90`，跳过 `CreateFileA` 并自行弹栈 | 更彻底，但改动 22 字节 |
| ~~A2 初版~~ | ~~`B8 FF FF FF FF 90`（`mov eax,-1; nop`）~~ | ❌ **作废**：漏掉 `add esp,0x1C`，每次调用泄漏 28 字节 → 栈失衡崩溃 |
| A1 | 把两个文件名字符串前 3 字节改成 `nul`+`\0`，让路径指向 Windows NUL 设备 | 依赖系统保留设备名识别，有不确定性 |
| B | 发布包自带 `hzp_tools\out\` 空目录，让日志有确定落点 | 零风险，但用户目录里仍会出现该目录 |

> 注意：全 `.text` 内 `call CreateFileA` 共 **7 处**，仅 `0x10001A21`/`0x10001AA1` 属日志，
> 另 5 处（`0x100013F7`/`0x100017CE`/`0x10005DD8`/`0x10007C08`/`0x10007F51`）是图集/表/`c87_paths.txt` 读取，**不可动**。

### ★ 栈平衡论证（A2a 成立的根据，2026-10-11 23:45 反汇编确认）

`x_hook.log` 写入函数 `0x10001A60` 完整反汇编：

```
0x10001A60  push ebp
0x10001A61  mov ebp, esp
0x10001A63  push edi / push esi / push eax
0x10001A72  push 0x10041708 ; 拼路径 (lstrcatA)
...
0x10001A8D  push 0            ; hTemplateFile
0x10001A8F  push 0x80         ; dwFlagsAndAttributes = FILE_ATTRIBUTE_NORMAL
0x10001A94  push 4            ; ★ dwCreationDisposition = OPEN_ALWAYS
0x10001A96  push 0            ; lpSecurityAttributes
0x10001A98  push 3            ; dwShareMode
0x10001A9A  push 4            ; dwDesiredAccess = FILE_APPEND_DATA
0x10001A9C  push 0x10041708   ; lpFileName
0x10001AA1  call [0x1003f958] ; CreateFileA
0x10001AA7  cmp eax, -1
0x10001AAA  je 0x10001AD2     ; 失败 -> 静默跳过 WriteFile/CloseHandle
...
0x10001AD2  add esp, 4        ; 只弹入口的 push eax
0x10001AD5  pop esi / pop edi / pop ebp
0x10001AD8  ret               ; ★ ret 无立即数
```

- 7 个参数（28 字节）**靠 `CreateFileA` 自己 stdcall 弹出**；epilogue 的 `add esp,4` 只管入口的 `push eax`
- ⇒ **任何"跳过 CreateFileA"的补丁都必须自行 `add esp,0x1C`**，否则每次调用泄漏 28 字节 → 崩溃
- ⇒ A2a 保留调用、只改一个立即数，栈完全不受影响

参数序列与 c86 源码 `CreateFileA(file, FILE_APPEND_DATA, share, NULL, OPEN_ALWAYS, NORMAL, NULL)` **逐位吻合**，
同时坐实 `0x1003f958` = `CreateFileA`。

#### 补丁逻辑完整性验证（23:10，回应"语义是否反了"的质疑）

**结论：方向正确，未反。** 三条独立证据：

**证据 1 — `jne` 的方向**：`cmp cl, 1` / `jne 0x10004a22`
`jne` = 不相等才跳。`cl==1`（条件满足）时 ZF=1 → **不跳** → fall-through 进入 dump；
`cl!=1` → 跳 0x10004a22。故「跳转 = 不打 dump」。

**证据 2 — `td_already` 的跳转目标**（决定性）：
```
0x10004A47  cmp dword ptr [ecx*4 + 0x10089c50], edx   ; 比对 g_tdDumped[] 与 src
0x10004A4E  je  0x10004a22                            ; ★ 已 dump 过 -> 跳 0x10004a22
```
「这个 src 已经 dump 过了」显然必须跳过 dump —— 它跳的正是 `0x10004a22`。
⇒ **`0x10004a22` 确定是"不打 dump"的出口**。

**证据 3 — c86 源码交叉验证**（`version_proxy.c:2220-2227`，c93e 同源）：
```c
if (r && r->w == 512 && r->h == 128 && g_tdDumpedN < TDMAXDUMP && !td_already(src)) {
    g_tdDumped[g_tdDumpedN++] = src;
    CreateDirectoryA(TDDIR, NULL);
    td_dump_src(src, dst, r);          // 打 dump
}
if (!g_orig_UpdTex) return -1;
return g_orig_UpdTex(self, src, dst);  // ★ 无论是否 dump 都转发
```

**逐条回答质疑：**

| 问题 | 回答 |
|---|---|
| a. fall-through 走什么？ | **打 dump 后转发**。查重 `td_already` → 登记 `g_tdDumped[n++]=src` → `CreateDirectory` → `td_dump_src` 写 `_rgb.bmp`/`_a.bmp` → **`0x10004F18 jmp 0x10004a22`** → 转发 |
| b. `0x10004a22` 是"只转发"还是"含 dump 后转发"？ | 它是**共用出口**，代码本身只做转发（`call eax` + `ret 0xc`）。从条件分支直接跳来 = 只转发；从 `0x10004F18` 跳来 = dump 后转发 |
| c. 改成 0 后确实等于"永不 dump"吗？ | **是**。`cmp esi,0` → `setl` 得 `cl=(n<0)` 恒 0 → `and cl,al`=0 → `cmp cl,1` 不相等 → `jne` **恒跳** → 永远走转发，永不进入 fall-through 的 dump 路径 |

**关于"与上限 48 语义相反"**：不相反。`g_tdDumpedN < TDMAXDUMP` 意为
「已 dump 数量**还没到**上限 → 可以再 dump 一个」，即 `n<48` → dump、`n>=48` → 停。
补丁把 48 改成 0 = "上限为 0 → 一个都不 dump"，语义一致。
