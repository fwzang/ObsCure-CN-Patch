## 五、取回后的第一件事：源码 ↔ DLL 对应核验（本机做）

1. `version.dll` 的 SHA-256/MD5 与 D 盘已有副本核对（D 盘 md5 = `38c8ccd3`）
2. 源码 grep 以下符号/字符串，确认与 c93e 反汇编结论一一对应：
   - `g_rearmPending` / `g_postResetNeedRebuild` 的状态转换（CreateTexture 置位 → [D2]/watchdog 清除）
   - `[D2]` 的两处判断逻辑（帧差阈值 0x96 + 渲染静止标志 + TestCoop → 自绑）——**反汇编位置 FOFF 0x4BB6 与 0x4D27**
   - DrawPrimitive 计数器（`[0x10048c58]`）与静止标志（`[0x10041014]` = sete 比较）的写入逻辑
   - 自绑的 `push [g_bigTex]; push 0; push dev; call [g_orig_SetTexture]` 序列（FOFF 0x4C05 / 0x4D54）
   - `EXP_NO_QUERY` 的实际取值（c93e 发布版 = 启用，即 GetTexture 查询全关）
3. 编译复现实验（可选但强烈建议）：用源码 + 记录的宏重新编译，  
   比对导出表（17/17）与关键机器码特征；有差异则排查宏/环境差异
4. 核验通过后才进入「有条件自绑」的源码级设计（需先回答的 4 个问题见调查报告第五节）
