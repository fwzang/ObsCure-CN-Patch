> 生成时间：2026-10-10
> 游戏：Steam 版《ObsCure》（appid 254460）
> 本包 = **完整工作区 + 可玩成品**，可在另一台电脑直接接手开发。

---

## 0. 一句话概览

本汉化**不改游戏数据包格式**，而是用 **D3D9 代理（`version.dll`）** 在运行时：
把游戏自己的 512×128 字体图集**替换为 512×4096 大图集**，并注入中文 `.lng` 文本。
- 文本：`datapack.hvp` 里的 `en.lng` 记录，被替换为中文（3078 条 / 已入库 2823 条）
- 字体：D3D9 代理截获字体纹理，换成本项目生成的中文图集

## 5. 继续开发：编译 hook

### 5.1 唯一可信编译命令（**务必照抄**）
```bash
cd hook
python -m ziglang cc -target x86-windows-gnu -O2 -fno-sanitize=undefined \
  -shared -o version_cXX.dll version_proxy.c version.def -DEXP_NO_QUERY
```

### 5.2 三条铁律（血泪教训，违反会编出"游戏起不来"的 DLL）
1. **`version.def` 绝对不能漏** —— 它定义 version.dll 的 17 个导出。
   漏掉 → 编译器导出所有非 static 函数（实测 20 个）→ 游戏加载期导入失败、
   进程起不来、日志一行不写。
2. **宏名是 `EXP_NO_QUERY`**（不是 `NO_QUERY`）。写错等于查询总闸没生效，
   会编出高风险版本（切屏白屏）。
3. **编译后必校验导出数**：
   ```bash
   python 工具/check_exports.py <dll>
   # 必须输出 numFunctions=17，否则禁止装机
   ```

## 11. 发布前必办（2026-10-11 新增）

### 11.1 P0-1：c93e 会往游戏目录写调试快照 `__RUNTIME__*.bmp` —— **发布版必须关掉**

**已铁证归属 c93e**（三证据）：
1. 扫描 `hzp_tools/hook/` 下 **105 个 dll**，含 `__RUNTIME__` 字面量的**仅 `version_c93e.dll`**，c32~c86 全部 104 个零命中；
2. 游戏目录 `version.dll` md5 `38c8ccd30c8e8436bebbe63a364bb406` = c93e 本身；
3. c93e 装机 `10-11 21:43`，快照时间跨度 `10-11 21:46 ~ 22:45`，全在装机之后；c86 时期（10-10）零快照。

**行为**：每次启动重生，单次约 10 个，实测累计 150 个/ 34 MB。命名为
`__RUNTIME__f<flag>_s<srcAddr>_d<dstAddr>_512x128_{rgb,a}.bmp`，
尺寸恒为 `512x128`（grp1 字体纹理），落盘路径为**相对路径** `hzp_tools\out\`。
`_rgb`=彩色可见层，`_a`=灰度 alpha/形状层（符合「RGB=可见 / alpha=形状」约定）。
⚠ **仅删文件无效**，每次启动会重新生成。

**修法（5 步）**：
1. 从 E 盘补齐 **c93e 版 `version_proxy.c`** —— ★D 盘现有的 3060 行副本仍是 c86 时代，日志路径硬编码 `D://SteamLibrary//...`，**不是 c93e**，改它无效；缺它就改不动。
2. 加 `EXP_NO_DUMP` 开关（沿用 `EXP_NO_QUERY`/`EXP_NO_CREATE` 宏族，勿用裸名），作用域**仅限落盘**；建议顺带加 `EXP_NO_LOG`（`x_hook.log` 单次已膨胀到 2.7 MB）。
3. 重编译并校验：`python hzp_tools/out/check_exports.py <dll>` → **导出数必须 = 17**，否则禁止装机（`version.def` 漏掉会编出 20 个导出 → 加载期直接失败、日志一行不写）。
4. 实机四项验证全过：启动 / 切屏（Alt-Tab×2，`[RESET]`=0）/ 暂停（读档列表 8 条中文）/ 长跑 ≥30 分钟。附带确认不再生成快照。
5. 发布。

**回退**：装机前备份 `version.dll.bak_c93e_verified`。本项**只改 hook**，
`datapack.hvp`/`big_atlas_c.raw`/`table_c.bin` 保持 `e539d4e8`/`12879fb3`/`9cf562f5` 不动。

### 11.2 相邻事实（省得下次重查）

- `swap_mode.txt` / `c87_paths.txt` **不存在 = 默认档**；二者是「读不到即默认」的可选配置，删除零影响。

- **干净回退目标**：`hook/` 下 c86 及以前的 104 个 dll 均无落盘行为。

但它会引入**第二个 D3D9 代理**。用户实测与 c93e 并存**未崩溃**，判定为可共存。

装机物：`dinput8.dll`（md5 `b8c51891352e3e7bfc2c30f2c903b46c`）+ `scripts/obscure.asi` + `scripts/main.patch`。

### 11.4 「切屏后文字约 2 秒才出现」—— 已定性：hook 自身设计代价，与宽屏补丁无关（23:07）

⚠ **作废此前结论**：22:59 写的「主界面文字略慢 = 宽屏 patch 改 FOV 致重绘量增加」
**无任何证据**（推断当结论）。用户实测确认**与宽屏补丁无关**，装之前就有。

**用户实测**：切屏后约 2 秒 → **直接出现**（非淡入）→ 游戏内文字正常。

**日志实证**（切屏 f=544）：`[WD-B0] 看门狗因 stage0 不匹配退出 #1~#6`（f=546~556，每 2 帧一次，
