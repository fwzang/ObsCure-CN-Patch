## 一、项目概述

将 Steam 版《ObsCure》（育碧软件 / Hydravision Entertainment，appid 254460）完整汉化并打包为
可分发的 Windows 安装程序。v1.00 交付两个版本：

| 版本 | 体积 | 定位 |
|---|---|---|
| **精简版** | 34.56 MB | 仅汉化核心（文本 + 字库 + 贴图），适用于已持有正版且 Steam 基底正常的用户 |
| **加强版** | 1.56 GB | 含 ODE 兼容层与全量资源重打包，适合 Steam 文件损坏 / 需要 ODE 的用户 |

两个版本均含：启动强制免责声明弹窗、自动基底识别、自动备份、失败可一键还原。

## 二、技术路线（关键决策链）

### 2.1 文本层

- 语言文件为 `.hvp` 包内 `.lng` 记录，24 字节文件头 + 变长记录
- 记录结构：`[u16 BE 长度][body][meta 6 字节]`，最后一条无 meta
- `body[0]` 为类型标记：`0 = 8-bit(GBK)`、`1 = UTF-16LE 宽字符`
- EN / SP 各 3078 条，逐条 meta 完全相同 → 可按记录序号一一对应替换
- 写入采用**最小改动**策略（`write_minimal.py`），不移动任何数据偏移

### 2.2 字体层（项目最大技术障碍）

破解结论：**字体不是网格，而是「比例字体 + 逐字符字形表」**。

```
字体对象（56 字节）
+0x00 u32 字形表VA   +0x04 u32 记录数   +0x08 u32 图集宽   +0x0C u32 图集高
+0x10 u32 字形高     +0x14 u32 行高     +0x28 std::string 字体名

字形表：连续 10 字节/条 = [u16 字符码][u16 x][u16 y][u16 宽][u16 步进]
```

**字符码是 u16 → 原生支持中文码点**，追加记录即可渲染中文，无需 FreeType。

已验证结论：
- 全游戏 UI + 正文**只用 grp1 一套字体**（改其他组纹理名无效）
- 字符串内无法切换字体（FE0x 控制码仅被丢弃）
- 字号上限受引擎 24px 采样行带限制，26px+ 不可用 → 最终选定 **24px**

### 2.3 图集层

原图集为**双通道**设计：`RGB = 可见内容`（按亮度渲染）、`alpha = 形状标记`（不参与外观）。
重生成图集时必须保留完整 RGBA，否则 17 个功能图标会退化为白圆盘。

### 2.4 被证伪的路线（避免二代重走）

| 路线 | 结论 |
|---|---|
| 更换字体纹理名指向其他图集 | ❌ 全游戏只用 grp1，叠加不生效 |
| 字符串内嵌字体切换码 | ❌ FE0x 被丢弃 |
| 依赖多字体组扩容 | ❌ 容量瓶颈在单张 512×128 图集 |
| FreeType 接管 / cachpack 原地扩容 | ❌ usize/offset/追加均失败或崩溃 |

## 三、完整流程（可复制的操作顺序）

### 阶段 A：文本汉化

```
1. extract_steam_en.py     提取 EN 全部 3078 条 → TSV 批次
2. （人工/批量）翻译        TSV → 中文
3. build_zh_lng.py         生成 zh.lng（type=1 UTF-16），--verify 往返校验
4. write_minimal.py        最小改动写入 datapack.hvp
5. full_verify.py          全包逐字节对比，差异须收敛到预期最小集合
```

### 阶段 B：字库制作

```
6. 渲染 24px 中文字形 → 打包进图集（保留双通道 RGBA）
7. 字形表追加中文记录（只追加，不改原 150 条）
8. table_c.bin + big_atlas_c.raw 装机
```

### 阶段 C：贴图汉化

```
9. 官方中文贴图 → 保头替换 maps_pc 内 33 张纹理
10. full_verify.py 复验
```

### 阶段 D：安装器打包

```
11. make_manifest_diff.py  生成 manifest（★ payload 任何变更都必须重跑）
12. PyInstaller --onefile --windowed --icon app_icon.ico
13. append_payload_diff.py 追加 payload（★ 只能执行一次，重复会损坏包）
14. 四套测试：verify_installer / e2e_test / e2e_vanilla_test / gui_smoke
```

### 阶段 E：发布

```
15. 真实环境幂等冒烟（在已汉化机器上跑一遍安装逻辑）
16. GUI 启动检查（窗口渲染 / 无杀毒拦截 / 弹窗正常）
17. 固化检查点 release_checkpoints/ + md5 清单 + 交接说明
```

## 四、十条增量铁律（实战教训）

1. **字形表只追加** —— 改动原有记录会破坏西文渲染
2. **控制码标记守恒** —— 原记录的控制码标记必须原样保留
3. **贴图保头替换** —— 只覆盖像素区，文件头不能动
4. **改包只走 create** —— 禁止原地改 usize / offset
5. **缩包/移动数据是高风险** —— 会破坏所有后续资源的绝对偏移，一律「最小改动 + 留垃圾」
6. **0x00 填充看似无害** —— 实则会抹掉紧邻资源（曾导致 voices.txt 被清零、引擎崩溃）
7. **payload 变更必须重跑 manifest** —— 否则安装器报「请重新下载安装包」
8. **append 只能执行一次** —— 重复追加会损坏单文件包
9. **单变量 rollout** —— 每次部署只改一个变量，配好回滚再动手
10. **GUI 构建必须用系统 Python312** —— venv 缺 tkinter 运行时

## 六、安装器架构

```
Installer.__init__()      加载 manifest / 开发模式读 devdir
  ├─ detect_base()        基底识别：原版 Steam / 原版 ODE / 已汉化(Steam) / 已汉化(ODE)
  ├─ install()            备份 → 组件安装 → md5 校验
  ├─ uninstall()          依 added-list 还原
  └─ 混合态保护           检测到 dp 原版但 pack 非原版 → 明确拒绝并提示
```

**备份机制**：安装前把被覆盖文件复制到 `_obscure_backup/`，并记录 `_added_files.txt`
（本次新增、原本不存在的文件），卸载时按清单精确删除。
