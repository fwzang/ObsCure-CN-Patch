## 第一部分 · 引擎分析

### 1. 资源体系总览

游戏资源全部装在 4 个 HVP 大包里（自定义格式，非加密）：

| 包            | 大小     | 内容                                           |
| ------------ | ------ | -------------------------------------------- |
| datapack.hvp | ~695MB | 语言文件（lng）、文本、数据                              |
| cachpack.hvp | ~30MB  | 字体纹理、UI 图集（含 `textures/font_holstein16.tga`） |
| strmpack.hvp | ~666MB | 流媒体资源                                        |
| kinepack.hvp | ~116MB | BIK 视频                                       |

HVP 格式（已 100% 破解，可直接读写）：

```
文件头 24 字节 + 目录区
目录项（每项紧贴排列）: [u32 BE nameLen][name][25B meta]
  meta[0:4]   = 名字长度 + 29
  meta[11:13] = 【下一个资源】压缩大小 (BE u16)
  meta[21:25] = 【下一个资源】绝对偏移 (BE u32)
⚠ 关键语义：资源 N 的数据由【前一个】目录项描述（末项为哨兵）
压缩流：zlib（raw deflate 裸流，无包头偏移）
```

**改包铁律**（血泪教训，全部踩过）：

1. 字段语义必须「名字/offset/内容」三者绑定验证后才可信；
2. 永远「最小改动 + 留垃圾」：只覆盖目标数据、后续资源偏移不动（write_minimal.py 是参考实现）；
3. 0x00 填充会抹掉隔壁资源（voices.txt 曾被清零 → 启动崩溃）；
4. 每次改包必须全包逐字节 diff（full_verify.py），把差异收敛到预期最小集合。

### 2. 语言文件（.lng）格式 —— 100% round-trip 验证

```
24 字节文件头
普通记录: [u16 BE L][body: L 字节][meta: 6 字节]
最后一条: [u16 BE L][body: L 字节]        ← 无 meta
body[0] = 类型: 0=单字节(GBK/ASCII)  1=UTF-16LE 宽字符
  type=1 时 body[1] 是前缀字节，body[2:] 才是文本   ← 旧提取器在这里翻过车
meta 6 字节：EN/SP 版逐条相同 → 按记录序号一一对应，可整段照抄零售版
```

- Steam 版 3078 条；零售官方中文 3070 条 100% 闭环。
- **写中文记录的编码契约**：`01 <UTF-16LE> 00 00`（缺 01 标记引擎按单字节解析 → 乱码）。
- 游戏当前实际消费 datapack 内 en 槽（0x29744622）；sp 槽 0x2976BBA3、目录项在 0x117E2。

### 3. 字体系统（本项目最大逆向成果）

**字体不是 16×16 网格，而是「比例字 + 逐字符字形表」**：

```
字体对象 56 字节（exe 0x5B760 初始化，共 5 组）:
  +0x00 u32 字形表VA   +0x04 记录数   +0x08 图集宽  +0x0C 图集高
  +0x10 字形高  +0x14 行高  +0x28 std::string 字体名
字形表: 每条 10 字节 = [u16 字符码][u16 x][u16 y][u16 宽][u16 步进]
  字符码 u16 → 原生支持中文码点，加记录即可渲染
```

| 组                | 表VA      | 表文件偏移    | 条数  | 图集      | 字形高 |
| ---------------- | -------- | -------- | --- | ------- | --- |
| grp1 holstein24  | 0x696380 | 0x293F80 | 150 | 512×128 | 24  |
| grp2 holstein30  | 0x696960 | 0x294560 | 71  | 512×128 | 35  |
| grp3 lucida10    | 0x696C28 | 0x294828 | ?   | 512×128 | 39  |
| grp4 buttons_360 | 0x696E58 | 0x294A58 | 12  | 128×16  | 13  |
| grp5 holstein16  | 0x696ED0 | 0x294AD0 | 28  | 256×256 | 32  |

**已证伪的路线**（不要重试）：

- ❌ 换字体纹理：全游戏 UI+正文只用 grp1 一套，多字体叠加无效；
- ❌ 字符串内切换字体（0xFE0x 码被丢弃）；
- ❌ 改 cachpack 字体资源大小/偏移/纹理名（只能原地等长替换，容量差 13 倍）。

**已验证通路（现役方案）**：

1. 图集外置：Hook 从游戏根目录读 `big_atlas_c.raw`（512×4096）+ `table_c.bin` 替换 grp1；
2. exe 加 PE 节 `.wfont` 放扩展字形表可行（但不能放 .data BSS，会被全局变量覆盖）；
3. 中文正文走 lng 记录 type=1 UTF-16LE。

**图集双通道机制（最重要）**：

```
RGB   = 可见内容（引擎按 RGB 亮度渲染；黑=不可见）
alpha = 形状标记（不参与外观）
新字必须: RGB = 米白×alpha/255 预乘, int() 截断
        （直通恒定色 → 边缘过亮；round() → 差 1）
24px 参数: TILE=26, PITCH=27, GH=24, ORIG_H=128；首行带需下移 2px 防压原区
```

### 4. Hook 系统（version.dll 代理）

- `version.dll` = d3d9 代理 + IAT hook，版本号 c86→c93e 迭代；
- 职责：截获 grp1 纹理创建/更新 → 换成外置 512×4096 图集；处理 D2/D2S（设备丢失/Reset）恢复；
- **D2/D2S 判据零硬编码**：FONT-CONFIRM 首帧登记 `g_grp1Hash`（FNV-1a 32KB 采样）+  
  `hh==g_grp1Hash` 跟随 → 图集内容变化无需改 hook；
- 已知坑：Reset 后只有组1 的 CreateTexture 先来（实测 38/38）；路径B 判据必须与路径A 组哈希一致（c92 修复）；
- 蓝屏问题（Reset 前只解绑 stage0）已知未修，暂缓。

### 5. 文本进入游戏的路径

- **Hook 运行时注入**（用户确认口径）：载荷 zh_only.bin（按 steam_idx 顺序拼接）+  
  zh_only_index.bin（3078×8B 小端索引）。
- ⚠️ 未决：version_proxy.c 源码中未见 zh_only 加载分支 —— 接手者第一件事是定位  
  载荷消费代码（成品DLL version_c92/c93e 或独立注入器）。
- datapack en 槽曾于 10-11 15:17 直接写包改造（47823B zlib @0x29744622 + 目录项下移 +  
  头部 0x24 字段变化，算法未破译，游戏可容忍）——这是一条备用路径 B。
- unified_zh.lng（3078 条闭环、meta 取零售版）是「完整文件替换」形态的语料成品，  
  可用于任何按 lng 结构消费的注入方式。

## 第二部分 · 汉化全流程（可复现）

### 0. 环境准备

- Python 3.12+（需 Pillow、numpy）；字体 ChillDuanSans_Bold.otf → `D:\Basic\`（或 BIGFONT 指定）
- 游戏根目录：`E:\SteamLibrary\steamapps\common\Obscure\`
- 原版备份：`hzp_tools/out/pristine/`（cachpack.hvp.orig 等）、`out/datapack.hvp.bak`

### 1. 文本流水线（数据源唯一：`out/corpus/final_zh.tsv`）

```
① 合并官方中文   python merge_retail_official.py --apply
② 非文本槽位保护 python fix_nontext_entries.py --apply   # 数字/符号/按键标签不可清空!
③ 图集生成       BIGSZ=24 BIGFONT="D:\Basic\ChillDuanSans_Bold.otf" python make_atlas_retail.py
                 → big_atlas_c.raw + table_c.bin + charset.txt（含原区 RGBA 保留 + 预乘 + 自检）
④ 四件套导出     python export_variants.py
                 → unified_zh.lng / zh_only.bin / zh_only_index.bin / en_zh_compare.tsv
⑤ 校验           verify_alignment.py（三份逐条一致、索引单调、闭环 3078）
```

译文优化循环：改 final_zh.tsv → 同步 batch_016.tsv → ③④ 重跑。  
对照材料：en_zh_compare.tsv（英中）+ merge_official_diff.tsv（官方 vs AI 取舍）。

### 2. 装机（当前未执行，前置确认项见交接报告第四节）

```
备份: big_atlas_c.raw + table_c.bin + version.dll（旧件保留）
覆盖: 交付包/1_装机文件/ 的图集与表 → 游戏根目录
文本: 按核实的注入方式装 zh_only 载荷 / unified_zh.lng
实测五步: 重启→主菜单(D2S) / Alt+Tab(D2) / 暂停菜单 / 长跑10分钟 / 新字场景抽查
验收场景: 开场提示(跳)、队友名(凯/莉)、存档页(悚)、道具描述(毫/闪/锤)、文档页(新字密集)
```

### 3. 游戏内自动化验证

- `ginput.py`：SendInput + KEYEVENTF_SCANCODE 注入（DirectInput 只读扫描码，  
  普通 keybd_event 无效）；可自动完成 主菜单→设置→新游戏→难度→进游戏→截图。
- `test3_watch.py` + 热键：切场景乱码抓取（F9/F10/F11/F2）。
- `d2_verify.py`：D2/D2S 行为验证。

### 4. 调试入口

- 日志：`out/versionproxy.log`、`out/x_hook.log`、`out/fileaccess.log`
- Hook 源码：`hzp_tools/hook/version_proxy.c`（3500 行，含 c62~c93e 全部演进注释）
- 字体表/图集自检：make_atlas_retail.py 尾部自动跑（原区一致性/越界/覆盖/墨迹预算）
